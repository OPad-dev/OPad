# TI ADS7028: the Hall Effect V3 module's ADC

8-channel, 12-bit, 1 MSPS SAR ADC with SPI. On the HE V3 module it is U4
(LCSC C880341, ADS7028IRTER, WQFN-16). It reads the three DRV5055 sensors, and
only digital SPI crosses the module cable (decision H1 in
`docs/specs/hardware-redesign-brief.md` on branch `hw/redesign`).

- **Datasheet:** SBAS978A, June 2019, revised May 2020.
  <https://www.ti.com/lit/ds/symlink/ads7028.pdf>, sha256
  `794590931f11f1ca11bd9e8fe4683c92ccd6af7a1101d5f5158373f17f54188c`
  (downloaded 2026-11-20). `scripts/fetch_datasheets.sh` fetches it.
- **Firmware:** `firmware/main/input/ads7028_regs.h` (registers and frame
  layout), `firmware/main/input/ads7028.c` (SPI3), and
  `firmware/main/diag/he_adc_test.c` (the board test).
- **Sibling:** the ADS7038 has the same pins, registers and frames. HE V2 was
  designed for it, and V3 uses the ADS7028 because JLCPCB stocks it
  (`hardware/pcb/V3/README.md` on `hw/redesign`). The ADS7028 adds an RMS
  module and zero-crossing detection, which OPad does not use.

## SPI

All from the datasheet, 8.3.14 and 7.6.

- **Mode:** SPI-00 (CPOL 0, CPHA 0) after power-up and after any reset. The
  other modes are set in `DATA_CFG.CPOL_CPHA`, and the write that sets them
  must itself use SPI-00.
- **SCLK:** 60 MHz max. CS high and CS low each last at least 200 ns.
  tCONV is at most 600 ns, and the cycle is at least 1 µs (1 MSPS).
- **Command frame:** 24 bits on SDI: opcode, then address, then data.

| Opcode | Command |
|---|---|
| `0x00` | no operation |
| `0x10` | read one register |
| `0x08` | write one register |
| `0x18` | set bits |
| `0x20` | clear bits |

- **Register read:** two frames. The first sends `0x10, addr, 0`. In the second,
  the first 8 SDO bits are the register. SDI may carry the next command then.
- **Writes** take effect at CS rising.

## Conversions

Sections 8.3.9 and 8.4.

- Output is MSB first: 12 bits, or 16 with averaging on (`OSR_CFG.OSR` > 0).
  It is optionally followed by 4 bits, the channel ID or status flags
  (`DATA_CFG.APPEND_STATUS`).
- **Manual mode** (the default, `SEQ_MODE` 00): the CS rising edge starts a
  conversion. A write to `CHANNEL_SEL.MANUAL_CHID` takes effect at that same
  edge. So the frame after the write samples the new channel, and the frame
  after that one returns its result: drop two frames after switching.
- **On-the-fly mode** (`SEQ_MODE` 10): the first 5 SDI bits of a frame select
  the channel. There is no latency.
- **Auto-sequence** (`SEQ_MODE` 01, `SEQ_START` 1): the ADC steps through the
  channels in `AUTO_SEQ_CH_SEL` in ascending order, one per frame.
- **Averaging:** after the host starts the first conversion, the ADC triggers
  the other N−1 internally (tAVG = N × tCYCLE). The 16-bit result can be read
  once they are done. 1 LSB = AVDD / 2^16.
- **`DATA_CFG.FIX_PAT`:** with it set, conversion data reads `0xA5A` every frame.
  The board test uses this to measure the cable's SPI margin.

## Registers OPad uses

Section 8.5. All other addresses are reserved.

| Addr | Register | Reset | Fields (bit) |
|---|---|---|---|
| 0x00 | SYSTEM_STATUS | 0x81 | RSVD (7, reads 1), SEQ_STATUS (6), RMS_DONE (4), OSR_DONE (3), CRC_ERR_FUSE (2), CRC_ERR_IN (1), BOR (0) |
| 0x01 | GENERAL_CFG | 0x00 | RMS_EN (7), CRC_EN (6), STATS_EN (5), DWC_EN (4), CH_RST (2), CAL (1), RST (0) |
| 0x02 | DATA_CFG | 0x00 | FIX_PAT (7), APPEND_STATUS (5:4), CPOL_CPHA (1:0) |
| 0x03 | OSR_CFG | 0x00 | OSR (2:0): 0 none, 1-7 = 2-128 samples |
| 0x04 | OPMODE_CFG | 0x00 | CONV_ON_ERR (7), CONV_MODE (6:5), OSC_SEL (4), CLK_DIV (3:0) |
| 0x05 | PIN_CFG | 0x00 | 1 = that channel is a GPIO |
| 0x10 | SEQUENCE_CFG | 0x00 | SEQ_START (4), SEQ_MODE (1:0) |
| 0x11 | CHANNEL_SEL | 0x00 | ZCD_CHID (7:4), MANUAL_CHID (3:0) |
| 0x12 | AUTO_SEQ_CH_SEL | 0x00 | 1 bit per AIN, all R/W: the board test's register walk uses it |

- **BOR:** set at power-up, at a brown-out and at `RST`. Clear it by writing 1.
  If it is set again later, AVDD dipped.
- **CRC_ERR_FUSE:** the power-up configuration did not load. A reset or an AVDD
  power cycle re-checks it.
- **RST:** resets every register. It takes at most 5 ms (tRST), the same as
  power-up (tPU, with 1 µF on DECAP).
- **CAL:** offset calibration. The bit clears itself when calibration is done.

## CRC

Section 8.3.6. The driver will need CRC once key input runs over this link
(brief, `hw/redesign`).

`GENERAL_CFG.CRC_EN` turns CRC on both ways. It uses CRC-8-CCITT
(x^8 + x^2 + x + 1). A frame that fails the check is ignored and sets
`CRC_ERR_IN`. All writes except to 0x00 and 0x01 are then blocked until the bit
is cleared by writing 1. The datasheet's text says the CRC is appended "to every
byte". The exact frame layout with CRC on is not spelled out in the sections
read for this note: check the datasheet's CRC figures before implementing it.
